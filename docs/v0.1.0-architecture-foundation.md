## **Critical Technical Lessons**

### **1. Data Consistency is Paramount**

#### **Field Name Standardization**
**Problem Solved**: CloudScript was saving `isCorrect: true`, but UI components expected `correct` field.

**Solution Established**:
```typescript
// CloudScript (MUST match UI expectations)
humanPerformanceData.push({
    correct: true,  // Standardized field name
    // ... other fields
});

// UI Components (consistent access pattern)
const humanCorrect = humanResult?.correct || false;
```

**Lesson**: Establish and enforce consistent field naming conventions across all system boundaries.

#### **Time Unit Standardization**
**Problem Solved**: Mixed usage of milliseconds and seconds across different components.

**Solution Established**:
```typescript
// Client sends seconds to CloudScript
timeElapsed: Math.floor((Date.now() - sessionStartTime) / 1000)

// CloudScript processes seconds
const timeInMinutes = Math.ceil((timeElapsed || 0) / 60);

// UI displays seconds (no conversion)
{humanResult.timeElapsed.toFixed(1)}s
```

**Lesson**: Standardize units at system boundaries and maintain consistency throughout the pipeline.

### **2. Event-Based Metrics Enable Rich Analytics**

#### **Real Step Counting Implementation**
**Problem Solved**: Hardcoded step count of 100 for all puzzles.

**Solution Established**:
```javascript
// CloudScript - Event stream analysis
function getStepCountFromEvents(playFabId, sessionId) {
    const events = server.GetPlayerEvents({ PlayFabId: playFabId });
    let stepCount = 0;

    if (events && events.History) {
        for (let event of events.History) {
            if (event.EventName === "SFMC" &&
                event.EventData?.sessionId === sessionId &&
                event.EventData?.event_type === "cell_change") {
                stepCount++;
            }
        }
    }

    return stepCount > 0 ? stepCount : 100; // Safe fallback
}
```

**Lesson**: Leverage PlayFab's event system for rich metrics while maintaining fallback defaults for reliability.

### **3. API Integration Requires Defensive Programming**

#### **ID Format Normalization**
**Problem Solved**: Different ID formats across APIs caused lookup failures.

**Solution Established**:
```typescript
// Robust ID conversion utility
export const idConverter = {
    normalizeToArcId(id: string): string | null {
        if (!id) return null;
        if (/^[a-f0-9]{8}$/.test(id)) return id; // Already ARC format
        const match = id.match(/ARC-[A-Z0-9]+-([a-f0-9]{8})/);
        return match ? match[1] : null;
    }
};
```

**Lesson**: Always implement defensive ID normalization when integrating multiple APIs with different conventions.

#### **Batch Processing with Individual Error Handling**
**Problem Solved**: Single API failure breaking entire comparison view.

**Solution Established**:
```typescript
// Promise.allSettled prevents cascade failures
const requests = puzzleIds.map(async (puzzleId) => {
    try {
        const stats = await this.getPuzzleExplanationsStats(puzzleId);
        results.set(puzzleId, stats);
    } catch (error) {
        console.warn(`Failed to load AI stats for ${puzzleId}:`, error);
        // Don't add to results - graceful degradation
    }
});

await Promise.allSettled(requests); // Continue processing all puzzles
```

**Lesson**: Design API integration patterns that fail gracefully and don't cascade errors.

### **4. User Experience Requires Progressive Enhancement**

#### **Loading States and Error Boundaries**
**Implementation Pattern**:
```typescript
// Comprehensive state management
const [isLoading, setIsLoading] = useState(true);
const [error, setError] = useState<string | null>(null);
const [comparisonData, setComparisonData] = useState<ComparisonData[]>([]);
```

**Lesson**: Always implement comprehensive loading, error, and empty states for production-ready user experiences.
